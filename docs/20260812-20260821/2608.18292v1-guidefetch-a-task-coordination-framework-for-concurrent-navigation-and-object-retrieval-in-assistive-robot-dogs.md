## 摘要
设想一个机器人导盲犬引领一位盲人用户到可用座位，同时另一个辅助机器人犬并发地取一杯咖啡并送到同一座位。这种情境促使并发执行，因为导航和物体取回可以重叠。一个句法上有效的大语言模型（LLM）计划仍可能违反具身约束，而看起来成功的控制器运动本身并不能确定任务完成。我们引入\textsc{GuideFetch}，一个由异构引导者和取回者团队进行并发导航与物体取回的协调框架。LLM从自然语言指令中实例化一个基于调度条件的四动作模式。在执行前，机器人、技能和目标别名被标准化，并针对已注册目标、机器人能力和选定调度对提议的动作进行验证。随后，机器人和物体的状态控制顺序与并行执行。在一项匹配的$2\times2$研究中，跨越90种场景和种子组合（360次执行），所有180个在线LLM响应均验证通过，无需回退或重放，并与相应的脚本化计划匹配。对于每个规划器来源，顺序和并行执行分别实现了$72/90$和$71/90$的操作成功。在两种调度均完成的56个案例中，并行执行平均将完工时间缩短了41.3\%。在此受控环境中，角色专业化和动作重叠缩短了已完成任务的耗时，而状态检查则区分了计划有效性与已验证的任务完成。源代码将公开。

## Abstract
Consider a robot guide dog escorting a blind user to an available seat while a second assistive robot dog concurrently retrieves a cup of coffee and delivers it to the same seat. This setting motivates concurrent execution because navigation and object retrieval can overlap. A syntactically valid Large Language Model (LLM) plan may still violate embodiment constraints, and successful-looking controller motion does not by itself establish task completion. We introduce \textsc{GuideFetch}, a coordination framework for concurrent navigation and object retrieval by a heterogeneous guider and fetcher team. An LLM instantiates a schedule-conditioned four-action schema from a natural-language instruction. Before execution, robot, skill, and target aliases are normalized, and proposed actions are validated against registered targets, robot capabilities, and the selected schedule. Robot and object states then govern sequential and parallel execution. In a matched $2\times2$ study across 90 combinations of scene and seed (360 executions), all 180 online LLM responses validate without fallback or replay and match the corresponding scripted plans. For each planner source, sequential and parallel execution achieve $72/90$ and $71/90$ operational successes, respectively. Among the 56 cases completed by both schedules, parallel execution reduces mean makespan by 41.3\%. Within this controlled setting, role specialization and action overlap shorten completed missions, while state checks distinguish plan validity from verified mission completion. Source code will be available.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心场景**：一个机器人导盲犬引领盲人用户前往可用座位，同时另一个辅助机器人犬（取物犬）去咖啡机取一杯咖啡并送到同一座位。这一场景天然适合**并发执行**——导航与物体取回在时间上可以重叠。
- **关键矛盾**：
  - 大语言模型（LLM）生成的计划即使**句法上有效**，也可能违反**具身约束**（例如把抓取任务分配给没有机械臂的机器人）；
  - 控制器的动作看起来"执行成功"，并不等于**任务真正完成**（例如物体未被夹稳、中途掉落）。
- **研究动机**：现有工作通常将"导盲导航"与"辅助取物"分别发展（如 ARP、Dusty 等系统），缺乏将两者统一到同一任务中的异构多机器人协调框架；而多机器人 LLM 规划工作虽涉及任务分解与分配，但很少区分**计划有效性、执行进度、任务完成**这三个不同层次的状态。
- **核心含义**：GuideFetch 将"语言意图"、"机器人执行"与"验证过的任务完成"三者解耦，通过角色专门化（guider 负责导航，fetcher 负责取物）和动作重叠来缩短完成时间，同时靠**状态化验证**确保符号层面的"计划成功"对应真实的物理任务完成。

## 2. 方法论：核心思想、关键技术细节与公式

### 2.1 总体流程

GuideFetch 的处理管线为：**自然语言指令 → LLM 实例化调度条件四动作模式 → 别名规范化与确定性验证 → 编译器构建依赖图 → 基于状态的顺序/并行执行 → 终端谓词验证完成**。

### 2.2 核心公式与定义

- **任务模型**：两个异构机器人 R = {rG（guider）, rF（fetcher）}，每个机器人具备技能集 Ci；动作词汇表 A = {navigate, move, grasp, carry}；场景注册表 Ω 包含取物站 gp、终点站 gf 和任务物体 o。
- **动作记录**：LLM 生成四个动作记录 vj = (kj, rj, aj, zj, pj)，其中 kj 是名义依赖层级索引，rj 是执行者，aj 是技能，zj 是目标，pj 是附加参数。
- **依赖图**：编译器构建 G = (V, E)，边 (vj, vℓ) 表示 vj 成功后方可启动 vℓ。图合法需满足：每台机器人和目标均注册、技能属于执行者能力集、动作结构符合所选调度。
- **运行状态**：每个动作状态 qj ∈ {pending, running, succeeded, failed}，前驱成功后且机器人空闲时才可运行。
- **顺序调度（Sequential，Pseq）**：fetcher 独自完成全程：
  Pseq := [F:move(gf), F:move(gp), F:grasp(o), F:carry(o, gf)]
  —— fetcher 先空载访问终点，再返回取物点，抓取并运送物体。
- **并行调度（Parallel，Ppar）**：guider 承担空载访问，fetcher 同时执行取物：
  Ppar := {G:navigate(gf) ∥ [F:move(gp), F:grasp(o), F:carry(o, gf)]}
  —— 两分支同时启动，fetcher 分支内部仍保持顺序约束（抓取需先到达取物点，搬运需先成功抓取和举起）。
- **完工时间模型**：Tseq = T_visit_F + T_return_F + T_grasp_F + T_carry_F；Tpar = max(T_nav_G, T_move_F + T_grasp_F + T_carry_F)。对比反映了"角色分配 + 动作重叠"的组合效果。
- **操作成功判定**：yop = bvisit ∧ bpickup ∧ bgrasp ∧ blift ∧ bretain ∧ bdelivery，即目标到达、取物点到达、双侧接触抓取、抬起、保持、辅助递送六项状态检查全部为真。

### 2.3 关键设计细节

- **规划与验证分离**：LLM 只负责输出结构化 JSON 动作记录；确定性验证器负责规范化机器人/技能/目标别名、检查所有四个动作是否存在、执行者能力是否匹配、carry 动作是否保留已注册物体、结构是否符合选定调度。**拒绝时不回退、不重放**，新响应需重新通过同一套检查。
- **执行机制**：所有活跃机器人共享同一个仿真时钟（200 Hz），各分支由本地状态事件推进。并行任务中，guider 到达终点后保持位置等待，featcher 不受 guider 到达约束即可开始操作，不插入固定等待间隔。
- **机器人技能实现**：
  - Guider：基于 PPO 训练的循环策略，输入 180 维平面激光雷达测量 + 11 维状态向量（目标几何、基座速度、身体朝向、上一步动作等），配合路点进度盾实现运动学传输，到达终点 0.20 m 范围内即满足导航条件。
  - Fetcher：基于 ALORE 的腿部运动策略 + 关节空间手臂编排 + 世界坐标系逆运动学；抓取需物体双侧接触；举起需峰值抬升 ≥ 30 mm；保持门控（200 Hz 下 1.0 s）需：保留抬升 ≥ 20 mm、双侧接触 ≥ 80% 帧且最后一帧仍接触、目标与支撑碰撞体分离 ≥ 5 mm、物体倾斜 ≤ 17°、抓取参考点到末端执行器坐标系原点距离 ≤ 0.25 m。只有通过预运输门控后，物体姿态才与末端执行器同步进入辅助运输。
- **完成检查**：终点访问、取物点到达、抓取、抬起、保持、递送均由仿真状态测量得到，失败即终止相关依赖动作；路径长度仅作记录，不构成额外成功条件。

## 5. 实验数量与充分性

- **总实验规模**：3 场景 × 30 种子 × 4 条件 = 90 个匹配组合 × 4 = **360 次独立仿真执行**；其中在线 LLM 规划响应 180 个。
- **各项分析的数量基础**：
  - 规划有效性：180/180 在线响应验证通过且与脚本化计划匹配。
  - 操作成功率：每条件 90 次执行，顺序与并行分别为 72/90 与 71/90。

## 6. 主要结论与发现

1. **计划有效性 ≠ 任务成功**：180 个在线 LLM 响应全部首次通过验证且与脚本化计划一致，但操作成功率仅约 80%，说明问题不在规划层面而在物理执行层面。
2. **并行调度显著缩短任务时间**：56 个共同成功案例中，平均完工时间从 164.78 s 降至 96.79 s，平均缩短 41.3%（1.70× 加速，配对均值差异 67.99 s，p < 0.001）；按场景看，Home 缩短 39.5%、Supermarket 缩短 19.1%、Hospital 缩短 48.6%。
3. **提速来源因场景而异**：Home 和 Supermarket 中并行团队总行驶距离反而更长（24.95 m vs 22.05 m；16.76 m vs 14.86 m），提速来自**时间重叠**；Hospital 中角色重新分配还消除了 fetcher 的长距离空载往返，总行驶距离由 68.25 m 降至 40.60 m。
4. **操纵是唯一瓶颈**：所有失败均发生在运输前的抓取/举起/保持阶段；没有任何案例失败于计划验证或取物点到达，并行条件下所有 guider 都成功到达导航目标。顺序与并行的成功率差异（72 vs 71）完全由 fetcher 操纵决定。
5. **成功案例的物理验证达标**：143 次成功的脚本化执行全部在运输前通过双侧接触、抬升和保持门控，平均峰值抬升约 66–70 mm、保持抬升约 62–63 mm。

## 7. 优点

- **概念区分清晰**：明确区分"计划有效性"、"执行进度"与"任务完成"三个层次，并以状态谓词（如双侧接触、抬升高度、保持门控）作为完成判据，避免了"看起来成功"的假阳性。
- **LLM 与确定性验证互补**：LLM 只负责从自然语言实例化结构化动作记录，能力检查、别名规范化、调度结构验证交给确定性代码，兼顾灵活性与可靠性；拒绝时不回退不重放，设计更简洁可控。
- **实验匹配度高**：2×2 匹配设计 + 固定控制器/扰动/超时，使得调度对比能干净地归因于角色分配与动作重叠；成功后才比较完工时间，杜绝"失败快跑"的统计偏差。
- **统计严谨**：使用 Wilson 置信区间、自举配对区间、符号翻转检验，报告了置信区间与显著水平。
- **失败归因清晰**：借助统一的运行记录（场景、种子、规划器、调度、状态转换、时限等），可将每个失败追溯到规划、执行或状态检查层，并给出三类具体的失败模式。
- **应用的现实意义**：功能专门化（导盲、取物）与动物导盲犬/服务犬分工的社会实践相呼应，具备明确的助残应用价值。
